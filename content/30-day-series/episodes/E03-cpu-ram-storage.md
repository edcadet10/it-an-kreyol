# E03 — CPU, RAM, ak storage

## Learning objective

The learner can match CPU to executing instructions, RAM to temporary working data, and storage to persistent files/apps.

## Audience problem

“This phone has 8 GB” is ambiguous: buyers and troubleshooters confuse RAM with storage and expect either number to explain all performance.

## Draft beats

- **Hook draft:** “De telefòn ka toude gen ‘8 GB,’ men chif yo pa toujou vle di menm bagay.”
- CPU: performs/coordinates instruction work; avoid calling it literally a human brain.
- RAM: fast working area for active programs; contents are generally not the user's long-term file store.
- Storage: keeps apps and files when the device is not actively using them.
- Performance depends on the whole system and workload, not one number.

## Visual

Use a worker (`CPU`), a small worktable (`RAM`), and a cabinet (`storage`). Add “analogy, not exact architecture” in the brief, not necessarily on screen.

## Knowledge check / CTA

“Si w ap louvri twòp app ansanm, ki resous ki ka vin sere pi vit: RAM oswa espas foto w yo?”

## Evidence

- [IBM — What is computer hardware?](https://www.ibm.com/think/topics/hardware)
- [Microsoft Learn — Exploring basic computer concepts](https://learn.microsoft.com/en-us/training/paths/explore-basic-computer-concepts/)

## Review flags

- Creator technical review must check every analogy and remove “CPU is the brain” as an unqualified definition.
- Do not promise that adding RAM or storage always makes a device faster.
