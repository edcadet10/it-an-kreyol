# E11 — Kijan pou mande IT èd

## Learning objective

The learner can make a useful support request containing the goal, actual result, expected result, exact error, timing/scope, safe steps already tried, and device/app context—without sending secrets.

## Audience problem

“Li pa mache” gives a technician too little information, while screenshots can accidentally reveal passwords, addresses, or private messages.

## Draft beats

- **Hook draft:** “`Òdinatè a pa mache` pa yon move plent—men li pa ban nou ase tras pou n ede w vit.”
- Compare a vague request with a short structured one.
- Capture exact wording/error and when it occurs; do not paraphrase away useful detail.
- Include scope: one user/device/app or several?
- List only safe steps already tried; never send a password, MFA code, recovery code, or full private screenshot.

## Visual

Transform a fictional one-line ticket into five labeled fields. Blur or invent all identifiers.

## Knowledge check / CTA

“Ki pi itil: `Wi‑Fi pa mache`, oswa `Telefòn mwen konekte, men de website pa louvri depi 2:00; lòt telefòn nan mache`?”

## Evidence

- [BLS — Computer Support Specialists](https://www.bls.gov/ooh/computer-and-information-technology/computer-support-specialists.htm) for document/diagnose/guide duties
- The exact ticket structure is a project teaching pattern and must not be presented as a universal industry standard.

## Review flags

- Privacy review every example.
- Add a brief warning that trusted support should never need the user's password or MFA code.
