# E21 — Verite sou public Wi‑Fi

## Learning objective

The learner can make a risk-based public-Wi-Fi choice: verify the network, keep the device/browser updated, use encrypted connections, protect accounts with MFA, and understand that HTTPS does not make a scammer honest.

## Audience problem

Two oversimplifications compete: “public Wi‑Fi is always unsafe” and “the padlock makes everything safe.” Neither is a useful complete model.

## Draft beats

- **Hook draft:** “Èske tout public Wi‑Fi danjere otomatikman? Repons lan pi nuanse.”
- Current FTC consumer guidance says widespread web encryption makes public Wi‑Fi usually safe for encrypted connections.
- Verify the network name; rogue look-alike networks remain possible.
- Look for HTTPS/update warnings, use MFA, and prefer a trusted mobile hotspot for especially sensitive work when practical.
- HTTPS protects the trip to the chosen site; an encrypted scam site can still steal what you give it.

## Visual

Three checks: correct network name, `https://` + real domain, updated device/MFA. Use invented network names and `example.com`.

## Knowledge check / CTA

“Si yon scammer gen HTTPS sou fo website li, èske kadna a rann scam lan onèt?”
