# Security and privacy reporting

Do not open a public issue containing a password, API token, MFA/recovery code, private message, personal address, unredacted account screen, raw participant data, or working malicious link.

If a public project artifact or video exposes sensitive information:

1. Contact the repository owner privately through a previously trusted channel or the contact route on the owner's GitHub profile.
2. Identify the affected episode/file without repeating the sensitive value.
3. State whether the exposure is still public and when it was observed.
4. Allow containment before public discussion.

For ordinary factual, language, accessibility, or non-sensitive security concerns, use the correction issue form.

The project will prioritize containment, rotate/revoke exposed credentials where applicable, preserve only safe evidence, correct affected material, and document a de-identified lesson.

This repository does not provide personalized incident response or account-recovery services. Maintainers and contributors will never ask for your password, MFA code, recovery code, or payment in order to review an issue.
